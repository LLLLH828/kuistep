# 跬步 · 阶段性总结（2026-09-21 · 更新）

## 一、项目定位

**跬步**——取自《荀子·劝学》"不积跬步，无以至千里"。面向 **N 家长 + N 孩子**的家庭协作学习平台，以**及时奖惩（小红花）**为基础，用 AI 解决家长没时间、没方法、英语发音不准等真实痛点。

**愿景**：AI 时代的教育平权。

**核心闭环**：家长设任务 → 孩子完成 → 家长确认 → 自动加小红花 → 兑换心愿。

### 2. 数据库（supabase/schema.sql）

- 9 张核心表：家庭、成员、五维模板、任务、流水、账户、心愿等
- RLS 行级安全：数据按家庭隔离
- 3 个触发器：
  - `on_auth_user_created` → 注册自动建家庭 + 15 条五维模板
  - `on_child_member_created` → 孩子成员创建时自动开通小红花账户
  - `on_reward_transaction_insert` → 插入流水时自动更新 reward_accounts 余额
- 幂等设计，可反复重跑；已在 Supabase 项目 `kuibue-dev` 执行成功 ✅

### 4. 中间件（src/middleware.ts）

- **旧版问题**：硬编码找 `sb-access-token` cookie（Supabase GoTrue-JS 时代格式），但 `@supabase/ssr` 写的是 `sb-<ref>-auth-token`，导致登录后被弹回 `/login`
- **修复**：改用 `@supabase/ssr` 的 `createServerClient` + `getSession()`（仅本地解析 JWT，不发网络请求，快），权威校验由服务端组件 `getUser()` 兜底
- 路由保护逻辑：未登录 → 跳 `/login`；已登录访问 `/login` → 直接进 `/parent`

## 三、踩坑记录（重要经验）

| 问题 | 教训 |
|------|------|
| `process.env[name]` 动态取值客户端永远 undefined | **Next.js 客户端环境变量必须静态字面量访问**（`process.env.NEXT_PUBLIC_XXX`） |
| 表内 `unique()` 约束不能带 where | 部分唯一索引需单独 `CREATE UNIQUE INDEX ... WHERE ...` |
| `drop trigger` 在建表前执行报错 | 调整语句顺序 |
| `.next` 缓存残留 | 切环境变量后清缓存重启 dev server |
| 邮箱验证限流 27 秒冷却 | 开发期关 Confirm email，上线换 SMTP |
| **中间件猜 cookie 名不对** | Supabase 新版 cookie 名含项目 ref，必须用 `@supabase/ssr` 的 `createServerClient` 走标准流程，不要硬编码 cookie 名 |
| **`getUser()` vs `getSession()` 性能差** | `getUser()` 每次发网络请求验证 JWT，从国内到 Supabase 海外节点数秒延迟；`getSession()` 仅本地解析 JWT，毫秒级。路由级快速放行用后者，权威校验用前者 |
| **`router.refresh()` 后 useState 不更新** | Next.js App Router 的 `router.refresh()` 会触发服务端组件重新渲染，但客户端组件的 `useState(initialProps)` 不会自动同步新 props。需要加 `useEffect(() => setState(newProps), [newProps])` |
| **`reward_transactions.member_id` 是孩子成员 ID** | 查流水不能用 `eq("member_id", familyId)`（永远查不到），必须先查 children 拿到 ids 再 `.in("member_id", childIds)` |
| **Tailwind 动态类名 purge** | `bg-green-${intensity}` 这类动态拼接的类名 JIT 检测不到，会被 purge 掉。必须用字面量三元表达式 `abs < 3 ? "bg-green-100" : "bg-green-200"` |
| **孩子没有 reward_account** | 即使有 `on_child_member_created` 触发器，page.tsx 兜底 insert 后没回填 account 对象，传给前端的 account 还是 null。兜底 insert 必须 `.select().single()` 然后回填 |
| **`router.push + router.refresh` 竞争** | 登录后先 `push('/parent')` 再 `refresh()`，但 refresh 刷新当前路由 `/login`，此时 cookie 已写入、中间件"已登录访问 /login 跳 /parent"规则触发，与 push 竞争。**`router.push` 本身就会挂载新组件，不需要额外 `refresh()`** |

## 四、当前状态

**闭环验证进行中——加分插入流水 + 触发器自动更新 reward_account 余额这条链路**。

已知：加分按钮点击后 `router.refresh()` 执行，但日历和总分没变化。可能原因：
1. 孩子没有 `reward_account`（`on_child_member_created` 触发器未执行）→ page.tsx 兜底已加
2. insert 静默失败（RLS 拒绝 / 字段约束）→ ParentDashboard 已加 alert 显式化
3. `router.refresh()` 后 useState 未同步 → 已加 useEffect 同步 props
4. 查流水用了 `member_id = familyId` → 已改成 `.in("member_id", childIds)`

需要用户触发一次加分按钮，看 alert 输出（或日历是否更新）来定位剩余问题。
