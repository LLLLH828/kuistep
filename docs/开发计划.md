# 跬步 开发计划（v0.1 讨论稿）

> **名称**：跬步（Kuǐ Bù），取自《荀子·劝学》"不积跬步，无以至千里；不积小流，无以成江海"。强调**及时、微小的奖惩对孩子成长的深远影响**——每一步都值得被看见，每一次进步都值得被激励。
> 定位：以及时奖励为驱动、AI 辅助为核心的家校协同学习陪伴平台
> 愿景：AI 时代教育平权 —— 让普通家庭低成本获得优质的学习陪伴与辅导能力
> 本文档为讨论稿，带 [待讨论] 标记的部分需要大家确认。

---

## 1. 产品原则

1. **简洁高效易操作**：家长每天 5~10 分钟完成布置与跟进；操作路径不超过 3 步。
2. **孩子视角是游戏，不是作业软件**：孩子看到的是"攒小红花、换心愿"的成长游戏。
3. **AI 只做引导，不做代劳**：讲解思路与启发，不直接给答案（教育理念 + 合规双重要求）。
4. **孩子端零付费、零广告**：所有收费面向家长账号。
5. **数据最小化**：只收集必要数据，未成年人信息加密存储，家长可导出/删除。

## 2. 目标用户与角色

| 角色 | 核心诉求 | 关键功能 |
|------|---------|---------|
| 学生（先聚焦小学 6-12 岁） | 有趣、及时反馈、看得见成长 | 小红花账户、任务打卡、AI 听写、错题本、问答助手 |
| 家长 | 没时间、不专业、怕麻烦、怕贵 | 10 秒布置任务、拍照批改辅助、奖励发放、周报、商城、账单 |
| 教师 | 时间少、不能增加负担 | 一键布置/一键表扬、班级激励（可选） |
| 管理员 | 运营与风控 | 用户/订单/内容/审核后台 |

## 3. 核心功能模块（按优先级）

### P0 — MVP：先跑通"任务 → 完成 → 奖励"闭环

1. **账号与家庭体系**
   - 手机号注册；家庭组（N 家长 + N 孩子，支持父母/老人多监护人共同参与）；邀请码绑定教师
   - 角色权限：学生端隐藏一切管理与付费入口

2. **奖励系统（产品灵魂）**
   - 小红花/积分账户：加分/减分、流水记录、备注原因、关联任务/场景
   - **德智体美劳五维评价模板**（默认内置，可增删改，家长自由选择启用哪些维度）：

     | 维度 | 典型加分项 | 典型减分项 | 默认分值 |
     |------|-----------|-----------|---------|
     | **德** | 主动帮助他人、礼貌待人、承认错误 | 撒谎、没礼貌、欺负同学 | ±1~3 |
     | **智** | 作业全对、主动提问、考试进步、错题订正 | 作业拖沓、考试退步、学习分心 | ±1~5 |
     | **体** | 坚持运动、体育课表现好、按时作息 | 久坐不动、熬夜、挑食 | ±1~2 |
     | **美** | 画画/弹琴/书法展示、审美表达、整理房间 | 乱涂乱画、房间脏乱 | ±1~2 |
     | **劳** | 主动做家务、自己整理书包、帮家人做事 | 不做家务、丢三落四 | ±1~3 |

   - 每个维度下家长可**自定义添加/编辑/删除**具体条目和分值；也可创建"自定义维度"（如 财商、情商、表达力等）
   - 奖励项家长自定义：
     - 物质：玩具、书籍、文具、零食
     - 非物质：30 分钟游戏时间、周末公园、决定一顿晚餐、挑选一部电影
   - 兑换流程：积分换奖励 → 家长确认兑现 → 流水留痕
   - 防通胀机制：每日加分上限、系统根据历史数据给出奖励项定价建议
   - 防惩罚机制：减分幅度 ≤ 加分，单一事件减分不超过 3 分；家长可设置"每日减分上限"
   - 即时反馈：加分动画 + 音效 + 通知，减分需家长填写简短原因（孩子端可见）
   - 周期性可视化：周/月五维雷达图（**仅家长端可见**），一眼看到孩子在哪方面表现好、哪方面需要关注

3. **任务与打卡**
   - 家长布置任务（模板：听写 / 口算 / 阅读 / 背诵 / 复习 / 自定义），10 秒完成
   - 任务可关联德智体美劳维度 → 完成后自动按对应维度加分
   - 孩子完成打勾或拍照提交 → 家长一键确认加分
   - 每日/每周任务视图 + 倒计时提醒
   - 任务可设"必须完成"或"可选挑战"两种模式（前者有时间压力，后者是激励；可选挑战由家长设置积分倍率，如 1.5x、2x）

4. **AI 作业监听与解析（远期核心能力，先做基础版）**
   - 目标：**代替家长盯住微信群/钉钉群/飞书群里老师发的作业、通知、要求**，自动拆解成可执行的任务
   - 实现路径（分阶段）：
     - Phase 2 基础版：
       - 家长从微信群/钉钉群**复制粘贴或截图**老师的作业消息 → AI 解析提取关键信息（科目、内容、截止时间、要求）→ 自动生成任务
       - 支持语音转文字：家长录下孩子口头传达的作业 → AI 转文字并拆解
     - Phase 3+ 进阶版（依赖平台开放接口）：
       - 微信：通过**微信开放平台/服务号模板消息**获取作业通知（需学校/教师配合或用官方 API）
       - 钉钉/飞书：通过**钉钉开放平台/飞书开放平台**授权读取家长关联的班级群消息
       - 自动识别"这是作业"还是"这是通知"，前者拆解为任务，后者仅提醒
       - 多源合并：同一天不同群的同类作业（如语文抄写）自动合并，避免重复
   - ⚠️ 合规提醒：群消息读取需家长**主动授权**，不得静默抓取；仅解析公开的班级通知，不读取私人聊天

5. **AI 听写（英语优先，解决"家长读音不准"痛点）**
   - TTS 朗读单词/课文 → 孩子默写或跟读 → 自动判分 → 结果回传家长
   - 后续扩展：语文词语听写、课文跟读评分

6. **家长周报**
   - 本周任务完成率、加减分明细、AI 生成的一句鼓励语
   - 五维雷达图快照

### P1 — 第二阶段

7. **错题本**
   - 拍照 → AI 识别 → 按知识点归类 → 周期性复习提醒
   - ⚠️ 采用引导式讲解（先提示思路，家长/孩子确认后再展开），规避"拍照搜题"红线

8. **AI 批改辅助**
   - 拍作业 → AI 检查标注 → 家长复核确认（定位"辅助家长"，AI 不直接判给孩子）

9. **兴趣拓展**
   - 每日一条"小知识 / 小实验 / 小问题"推送，可积分

10. **微信通知**
   - 加减分、任务完成、周报通过微信服务号推送家长
   - AI 作业解析结果也通过微信推送（家长不用频繁打开 App）

### P2 — 第三阶段

11. **知识库问答助手（孩子端）**
    - 情绪疏导、学习方法小妙招、课内外视野拓展、知识积累
    - 安全设计：
      - 少儿内容分级 + 敏感话题（心理危机、暴力等）立即转介家长并提示专业渠道
      - 全量对话日志家长可见
      - 防诱导（防止孩子让 AI 代写作业，回答采用苏格拉底式引导）

12. **教师端**
    - 一键布置 / 一键表扬、班级小红花墙（轻到"老师只点一下"）

13. **收费体系**
    - 会员订阅（AI 次数额度）、商城实物礼品兑换、订单与支付

## 4. 奖励体系设计原则

- **可加可减**：减分幅度小于加分，减分前有规则提示，避免变成惩罚工具伤害孩子。
- **德智体美劳五维并重**：避免单一学科导向，鼓励全面成长。
- **物质 + 非物质并重**，家长完全自定义。
- **长期导向**：奖励频次设计上逐步递减，引导从"物质奖励"过渡到"成长可视化 + 精神激励"，避免孩子只为小红花学习（这是产品教育理念的核心，也是与竞品差异化所在）。
- **防通胀**：系统根据历史数据给出奖励定价建议。
- **防惩罚**：减分有上限，且需家长填写原因，避免家长情绪化操作。

## 5. 技术架构

### 5.1 总体策略：PWA 优先

- **理由**：一套代码覆盖手机/平板/PC；免应用商店审核、更新即时；开发与维护成本最低。
- **可用的端能力**：添加到主屏幕、离线缓存（Service Worker）、Web Push、摄像头拍照（作业）、麦克风录音（跟读）、TTS 播放。
- **iOS 注意事项**：
  - 推送通知需用户先"添加到主屏幕"（引导安装流程要设计好）；
  - Safari 对 7 天不活跃的站点可能清理存储，核心数据必须在服务端；
  - 部分高级 API 受限，功能设计需留退路。
- **儿童手表评估**：
  - 小天才/华为/小米等主流儿童手表为封闭系统，**无法安装 PWA 与第三方应用**；
  - 短期：小红花变动推送至家长微信，孩子在自己设备上查看；
  - 中期：家庭侧 Apple Watch / Wear OS 可做极简查看页（PWA 或小组件）；
  - 长期：关注小天才等开放平台合作机会，或短信/微聊触达。
  - **结论：手表端不进入 MVP，列为远期探索。**

### 5.2 技术栈建议（可讨论）

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | Next.js + TypeScript + TailwindCSS + PWA（Workbox/Serwist） | SSR 利于 SEO 与首屏 |
| 后端 | Next.js API 起步，复杂后拆分 NestJS | MVP 阶段保持简单 |
| 数据库 | PostgreSQL（Supabase 加速起步）+ Redis | Supabase 自带认证/存储/实时，省 2-4 周 |
| 对话/批改/讲解 | 豆包 / 通义千问 / DeepSeek / 智谱 GLM | 必须选已备案模型 + 自建内容审核层 |
| 语音识别（跟读判分） | 讯飞 / 火山引擎 | 有儿童语音优化 |
| TTS（听写朗读） | 火山 / 讯飞 | 英语发音质量优先实测对比 |
| 拍照识别 | 多模态大模型直接识图 | 省去传统 OCR 步骤 |
| 部署 | 国内云（阿里/腾讯）+ CDN | 域名需 ICP 备案 |

## 6. 合规与风险（重要，商用前必须逐条落实）

1. **教育监管**
   - 不做"拍照搜题"直接给答案模式（2021 年已被叫停），AI 一律引导式讲解；
   - 不做学科类在线培训，定位"工具 + 激励 + 素质拓展"；
   - 进入校园需教育 App 备案；个人/家庭使用暂不强制，商用化需持续关注政策。
2. **生成式 AI**：面向公众提供服务需完成算法备案；面向未成年人内容审核标准加严。
3. **未成年人保护**：处理不满 14 周岁未成年人个人信息需监护人同意（《未成年人网络保护条例》）；数据最小化、加密存储、可删除。
4. **资质**：ICP 备案（必须）；开通收费功能需经营性 ICP 许可证。
5. **付费安全**：孩子端不出现任何付费/充值/广告入口，收费全部由家长账号完成。

## 7. 商业模式

| 层级 | 内容 | 目的 |
|------|------|------|
| 免费 | 基础任务/奖励 + 每日限量 AI 次数 | 获客与口碑 |
| 会员订阅（家长购买） | 月/季/年，解锁 AI 听写/批改/错题本额度与周报 | 核心收入 |
| 商城 | 虚拟奖励模板免费；实物礼品兑换（初期家长自备，后续再接供应链） | 增值 |
| 教师端 | 免费 | 获客与传播，班级版远期 |

## 8. 开发路线图

| 阶段 | 周期 | 内容 | 里程碑 |
|------|------|------|--------|
| Phase 0 | 1-2 周 | 需求确认、原型图（Figma）、UI 风格定稿（儿童大按钮 + 家长侧适中信息密度）、账号体系设计 | 原型评审通过 |
| Phase 1（MVP） | 4-8 周 | 家庭账号 + 小红花账户 + 任务打卡 + 英语 AI 听写 + 家长确认 + 基础通知 | 5-10 个家庭内测闭环跑通 |
| Phase 2 | 4-6 周 | 错题本、AI 批改辅助、家长周报、商城兑换、微信通知 | 内测家庭留存验证 |
| Phase 3 | 持续 | 知识库问答、教师端、收费系统、兴趣拓展内容库 | 公测 + 商业化 |

## 9. 待讨论问题

1. 目标年龄段与学科范围？建议：小学 1-6 年级，英语 + 语文先做，数学做口算。
2. 教师端是否进入 MVP？建议：不进，先做家长侧闭环，教师端 Phase 2+。
3. 减分规则怎么定才能不伤孩子？减分上限、是否需要孩子申诉机制？
4. AI 讲解的"度"：引导到什么程度展开答案？是否家长可配置？
5. 预算与团队规模？决定用 Supabase/BaaS 还是自建后端。
6. 首批种子用户来源？建议：身边家长群 / 同学班级。
7. UI 风格：儿童端的插画风格、配色（明快暖色 vs 清新冷色）？
